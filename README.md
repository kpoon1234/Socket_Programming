# Socket Programming

โปรเจกต์แอปแชตด้วย Python 3 และ TCP Socket

## สถานะปัจจุบัน: Part 1 ขั้นที่ 2

ทดสอบในเครื่องเดียวที่ `127.0.0.1:5000` โดย Client ส่งหนึ่งข้อความให้ Server และ Server ตอบกลับมาที่ Client คนเดิม

ใช้โมดูลมาตรฐานของ Python จึงไม่ต้องติดตั้งแพ็กเกจเพิ่มสำหรับขั้นนี้

## วิธีทดลอง

เปิด Terminal สองหน้าต่างในโฟลเดอร์โปรเจกต์นี้

**Terminal 1 — เริ่ม Server ก่อน**

```bash
python3 server.py
```

จะเห็นข้อความ:

```text
Server รอ Client ที่ 127.0.0.1:5000
```

**Terminal 2 — เริ่ม Client**

```bash
python3 client.py
```

เมื่อเห็นช่องพิมพ์ ให้พิมพ์ `สวัสดี` แล้วกด Enter จะได้รับ:

```text
คำตอบจาก Server: Server ได้รับข้อความแล้ว: สวัสดี
```

ทั้งสองโปรแกรมจบหลังทดสอบหนึ่งข้อความ หากจะทดลองอีกครั้ง ให้เปิด Server ใหม่แล้วจึงเปิด Client ใหม่ ใช้ `Ctrl+C` เพื่อหยุดโปรแกรมระหว่างรอได้

ถ้า Client แจ้ง `Connection refused` ให้ตรวจว่าเปิด Server ไว้ก่อนแล้ว หาก Server แจ้ง `Address already in use` ให้ตรวจว่า Server จากรอบก่อนหรือโปรแกรมอื่นยังใช้พอร์ต `5000` อยู่หรือไม่

## Flow และแนวคิดในโค้ด

```text
Server: socket → bind → listen → accept
Client: socket → connect → พิมพ์ข้อความ → encode UTF-8 → sendall
Client: shutdown(SHUT_WR) เพื่อแจ้งว่าส่งครบแล้ว แต่ยังรอรับได้
Server: recv จนครบ → decode UTF-8 → สร้างคำตอบ → sendall → ปิดการเชื่อมต่อ
Client: recv จนครบ → decode UTF-8 → แสดงคำตอบ → ปิด Socket
```

- `bind()` กำหนดที่อยู่และพอร์ตที่ Server เปิดรับ
- `listen()` เปิดรอการเชื่อมต่อ ส่วน `accept()` รอรับ Client และคืน Socket สำหรับคุยกับ Client คนนั้น
- `connect()` ให้ Client เชื่อมต่อ Server ตามที่อยู่และพอร์ต
- `encode("utf-8")` แปลงข้อความเป็นไบต์ก่อนส่ง ส่วน `decode("utf-8")` แปลงกลับเป็นข้อความ
- `sendall()` ส่งข้อมูลทั้งหมด หรือแจ้งข้อผิดพลาดหากส่งไม่สำเร็จ
- `recv()` รับข้อมูลได้ครั้งละบางส่วน จึงวนรับและเก็บรวมกันก่อนแปลงเป็นข้อความ
- `shutdown(socket.SHUT_WR)` ปิดเฉพาะฝั่งส่งของ Client เมื่อ Server รับข้อมูลที่ส่งมาจนครบ จะได้ `b""` จาก `recv()` และรู้ว่าสิ้นสุดข้อความแล้ว
- `with socket...` ช่วยปิด Socket เมื่อออกจากบล็อก รวมถึงเมื่อเกิดข้อผิดพลาด

ขั้นนี้ใช้หนึ่งข้อความต่อการเชื่อมต่อ ยังไม่ใช่การส่งต่อให้ Client อีกคน การส่งหลายข้อความบนการเชื่อมต่อเดิมด้วย JSON จะทำในขั้นที่ 3 และการรองรับหลาย Client พร้อมกันจะทำในขั้นที่ 4
