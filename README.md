# Socket Programming

โปรเจกต์แอปแชตด้วย Python 3 และ TCP Socket

## สถานะปัจจุบัน: Part 1 ขั้นที่ 3

ทดสอบในเครื่องเดียวที่ `127.0.0.1:5000` โดย Client ลงทะเบียนชื่อ แล้วส่งข้อความ JSON ให้ Server ได้หลายครั้งผ่านการเชื่อมต่อเดิม Server ตอบกลับ Client คนเดิมในแต่ละครั้ง

ใช้โมดูลมาตรฐานของ Python จึงไม่ต้องติดตั้งแพ็กเกจเพิ่มสำหรับขั้นนี้

| ไฟล์ | หน้าที่ |
| --- | --- |
| `server.py` | รอ Client ลงทะเบียนชื่อ ตรวจสอบคำสั่ง และตอบข้อความ |
| `client.py` | รับชื่อและข้อความจากผู้ใช้ ส่งคำสั่ง และแสดงคำตอบ |
| `protocol.py` | แปลง dictionary เป็น JSON เข้ารหัส UTF-8 และแบ่งข้อความด้วยตัวจบบรรทัด |

## วิธีทดลอง

เปิด Terminal สองหน้าต่างในโฟลเดอร์โปรเจกต์นี้

**Terminal 1 — เริ่ม Server ก่อน**

```bash
python3 server.py
```

จะเห็น `Server รอ Client ที่ 127.0.0.1:5000`

**Terminal 2 — เริ่ม Client**

```bash
python3 client.py
```

ตัวอย่างการใช้งาน:

```text
เชื่อมต่อ Server ที่ 127.0.0.1:5000 แล้ว
ชื่อของคุณ: kaopoon
ลงทะเบียนเป็น kaopoon แล้ว พิมพ์ /quit เพื่อออก
พิมพ์ข้อความถึง Server: สวัสดี
คำตอบจาก Server: Server ได้รับข้อความจาก kaopoon: สวัสดี
พิมพ์ข้อความถึง Server: ทดสอบข้อความที่สอง
คำตอบจาก Server: Server ได้รับข้อความจาก kaopoon: ทดสอบข้อความที่สอง
พิมพ์ข้อความถึง Server: /quit
ปิดการเชื่อมต่อแล้ว
```

`/quit` เป็นคำสั่งภายใน Client เพื่อออกจากลูปและปิด Socket ไม่ได้ส่งเป็นข้อความแชต ทั้งสองโปรแกรมจบหลัง Client ออก หากจะทดลองอีกรอบ ให้เปิด Server ใหม่ก่อนแล้วจึงเปิด Client ใช้ `Ctrl+C` เพื่อหยุดโปรแกรมระหว่างรอได้

ถ้า Client แจ้ง `Connection refused` ให้ตรวจว่าเปิด Server ไว้ก่อนแล้ว หาก Server แจ้ง `Address already in use` ให้ตรวจว่าโปรแกรมอื่นหรือ Server รอบก่อนยังใช้พอร์ต `5000` อยู่หรือไม่

## สิ่งที่เปลี่ยนจากขั้นที่ 2 และเหตุผล

### 1. ใช้ JSON บอกชนิดคำสั่ง

แทนการส่งข้อความเปล่า Client ส่งข้อมูลที่มีโครงสร้าง เช่น:

```json
{"type": "register", "name": "kaopoon"}
{"type": "message", "text": "สวัสดี"}
```

- `type` บอก Server ว่าต้องทำอะไร
- `register` แจ้งชื่อครั้งแรก ส่วน `message` ส่งข้อความหลังลงทะเบียนแล้ว
- Server ตอบรับชื่อด้วย `registered` ตอบข้อความด้วย `message` และแจ้งข้อมูลผิดด้วย `error`
- Server เก็บชื่อที่ลงทะเบียนไว้กับการเชื่อมต่อนี้ แล้วใช้ชื่อนั้นระบุผู้ส่ง ไม่อ้างอิงชื่อที่อาจแอบแนบมาในแต่ละข้อความ
- การแจ้งชื่อยังไม่ใช่ระบบยืนยันตัวตนหรือรหัสผ่าน และการตรวจชื่อซ้ำระหว่างหลาย Client จะทำเมื่อรองรับหลาย Client

### 2. ใช้ตัวจบบรรทัดแทนการปิดฝั่งส่งเพื่อแบ่งข้อความ

ขั้นก่อน Client ใช้ `shutdown(SHUT_WR)` เพื่อบอกว่าส่งครบ จึงส่งต่อไม่ได้อีกบนการเชื่อมต่อเดิม ขั้นนี้เติมไบต์ `\n` หลัง JSON แต่ละข้อความแทน ทำให้ส่งข้อความถัดไปผ่าน Socket เดิมได้

```text
{"type":"message","text":"ข้อความแรก"}\n
{"type":"message","text":"ข้อความที่สอง"}\n
```

ในตัวอย่าง `\n` แทนตัวจบบรรทัดจริงที่ส่งบนเครือข่าย ส่วนการขึ้นบรรทัดใหม่ภายในค่า `text` จะถูก `json.dumps()` แปลงเป็นอักขระ escape จึงไม่สับสนกับตัวจบข้อความ

### 3. เก็บข้อมูลใน buffer จนกว่าจะครบข้อความ

TCP ส่งข้อมูลเป็นกระแสไบต์ `recv()` หนึ่งครั้งจึงอาจได้รับครึ่งข้อความ หรือหลายข้อความรวมกัน

`receive_messages()` ทำงานดังนี้:

1. รับไบต์แล้วต่อท้าย `buffer`
2. ถ้ายังไม่พบ `\n` ให้รับเพิ่ม
3. เมื่อพบ `\n` ให้แยกบรรทัดแรกออกมา โดยเก็บส่วนที่เหลือไว้
4. แปลงไบต์ของบรรทัดที่ครบแล้วด้วย UTF-8 และแปลง JSON เป็น dictionary
5. ใช้ `yield` คืนข้อความทีละรายการ ถ้ามีบรรทัดอื่นครบอยู่แล้วก็คืนต่อได้โดยไม่ต้องรอข้อมูลเพิ่ม

`yield` ทำให้ฟังก์ชันเป็น generator ซึ่งหยุดพักและจำ buffer ไว้ได้ Server ใช้ `for` อ่านต่อเนื่อง ส่วน Client ใช้ `next()` รับคำตอบครั้งละหนึ่งรายการ จึงต้องสร้าง generator เพียงครั้งเดียวต่อการเชื่อมต่อ

หาก JSON ผิดรูปแบบ ไม่ใช่ object หรือการเชื่อมต่อจบโดยยังมีบรรทัดไม่ครบ จะเกิด `ValueError` Server จะพยายามแจ้ง `error` แล้วปิดการเชื่อมต่อนี้ ส่วนคำสั่งผิดหรือข้อมูลไม่ครบใน object ที่อ่านได้จะได้รับ `error` และสามารถส่งคำสั่งแก้ไขต่อได้

### 4. แยกกติกาที่ใช้ร่วมกันไว้ใน protocol.py

- `send_message()` ใช้ `json.dumps()` → เติม `\n` → เข้ารหัส UTF-8 → `sendall()`
- `receive_messages()` ใช้ `recv()` → เก็บ buffer → แยกบรรทัด → ถอดรหัส UTF-8 → `json.loads()`

ทั้ง Client และ Server เรียกใช้ฟังก์ชันเดียวกัน จึงไม่ต้องเขียนกติกาซ้ำสองที่

## Flow ปัจจุบัน

```text
Server: socket → bind → listen → accept
Client: socket → connect → ส่ง register
Server: เก็บชื่อกับการเชื่อมต่อ → ตอบ registered
Client: รับข้อความจากผู้ใช้ → ส่ง message
Server: อ่าน JSON ที่ครบแล้ว → ตรวจข้อมูล → ตอบ message
Client: แสดงคำตอบ → กลับไปรับข้อความถัดไป
Client: ผู้ใช้พิมพ์ /quit → ปิด Socket
Server: recv ได้ b"" → จบการเชื่อมต่อและจบโปรแกรม
```

ขั้นนี้ Server ยังดูแล Client เพียงคนเดียว และ Client รอคำตอบหนึ่งครั้งหลังส่งแต่ละข้อความ การรับหลาย Client พร้อมกัน การใช้ฟิลด์ `to` เพื่อเลือกผู้รับ และการส่งต่อระหว่าง Client จะทำในขั้นที่ 4
